Architecture

Architecture · sample-project

The technical companion to Working Files/product-plan.md. How the backpack inquiry CRM is built, and the full data model.

1. Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site that captures leads (sizing, materials, and laptop-fit questions about backpacks), and an /admin CRM where those leads are worked. /admin starts open and gets locked down with Supabase Auth later in the build.

2. How the pieces fit

Next.js (App Router)

Renders the public site and /admin. Server code handles form submissions and all database reads and writes.

Vercel

Hosts and deploys the app at sample-project-brown-iota.vercel.app. Environment variables hold every secret. A push deploys.

Supabase (Postgres)

The database. Accessed server-side only, using the service key. Secrets never reach the browser.

Resend

Sends the confirmation email when a lead comes in (wired in Build 2). Needs a verified custom domain; a vercel.app address can't be verified.

Environment variables
  • NEXT_PUBLIC_SUPABASE_URL — the address of the Supabase project.
  • NEXT_PUBLIC_SUPABASE_ANON_KEY — the public key, used later by Supabase Auth for the /admin login.
  • SUPABASE_SERVICE_ROLE_KEY — the secret key the server uses for every database read and write. Never sent to the browser.
  • RESEND_API_KEY — the secret key that lets the server send email through Resend.
  • NEXT_PUBLIC_SITE_URL — the live site address, used for links in emails and redirects.

3. The lead flow

  1. A visitor submits the form: name, email, optional phone, inquiry type (sizing, materials, or laptop_fit), laptop size, primary use, and a message.
  2. The server upserts a People row by email. A repeat email updates the existing person; it never creates a duplicate.
  3. The server creates a linked Contacts row in status new_lead.
  4. Resend sends the visitor a confirmation email.Build 2
  5. The operator sees the lead in /admin and works it: new_lead → contacted → discovery_call → proposal → won or lost.
  6. Each status change writes one activity_log row recording from_status, to_status, and actor.

5. Relationships

  • One Person has many Contacts.
  • One Contacts row has many activity_log rows.
  • One Person has many Orders.
